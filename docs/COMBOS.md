# Combo Tester

The Builder's right panel contains an ordered combo editor. Target settings and attack conditions live in a native dialog opened between Items and Skin. Target mitigation has a separate toolbar toggle; closing the dialog or switching mitigation off retains its values.

Use Q/W/E/R/AA quick buttons or the action selector for individual damage variants, recasts, and equipped active/passive item effects. Repeat, reorder, delete or clear steps. Build, rank, combat-input and target changes refresh automatic values. Changing champion clears the sequence. Unequipping an item or unlearning an ability marks existing steps unavailable rather than silently removing them. Expand a step to supply explicit damage/timing overrides; clear the fields or use **Use build values** to restore automatic calculation. Overrides are scenario values and do not scale with later build changes.

## Calculation contract

- `JS/shared/comboTester.js` schedules actions in user order. A start is the later of the previous cast's completion and the action's next availability. AA spacing is `1 / attacks per second`, not the attack-speed number itself. The final windup/cast is included in elapsed time.
- `JS/comboUI.js` adapts existing ability profiles and haste-adjusted cooldowns. All variants of a slot share its cooldown. Recasts require the preceding stage, respect supplied lockouts and known windows, and can run during the main cooldown. Last-recast cooldowns wait for an abandoned chain's known window to expire. Aatrox Q uses the source wrapper's cast time and the existing DPS recast interval; Aurora Q uses its first/recall damage formulas and source cast times, with a user-supplied recall interval because projectile distance matters.
- Explicit source cast times and channel durations are used when present. Basic-attack windup uses the source cast/total-time ratio divided by current attack speed. Missing timing is not assumed instantaneous. A repeated action with no known repeat cooldown requires a value; a single initial ready action does not.
- Each selected damage variant is one contribution. AA uses the attack model's base damage with averaged critical strikes, excluding separately modeled bonus rows. Add item and champion bonus triggers explicitly to avoid averaging procs or counting them twice. Passive conditions/cadences are assumed satisfied by the user's chosen sequence, not automatically built up. Spellblade entries share a cooldown group.
- Item damage uses a modeled single-proc value where available, otherwise a single unambiguous typed scalar from the already-resolved item description. Multi-part/alternative or missing item formulas remain unavailable. Active item cooldowns use the existing source resolver. Active cast times absent from the item model require an entry. Description-derived values carry the existing display precision.
- Damage uses current configured target health, resistances and penetration. The target health pool and champion combat conditions do not evolve after each step. There is no travel-time, movement, resource, buff-state, cooldown-refund, attack-reset or animation-cancel simulation. Special attack cycles such as Jhin reloads require scenario timing adjustments. Duration measures action execution, not the arrival of all projectiles or the final damage-over-time tick. Full-duration damage rows may need a longer cast/channel override.
- Unknown damage prevents a numeric total; unknown timing prevents a numeric minimum duration. Known damage and provisional timestamps remain visible. Invalid order, expired recasts and unavailable actions invalidate results. This is a configurable estimate, not a universal frame-accurate simulator.

## Verification

`npm test` includes scheduling, reciprocal attack speed, overlapping cooldowns, recast ordering/expiry, abandoned chains, shared variant cooldowns, and missing-data tests. `npm run test:combos` uses the same advanced fixtures and Playwright environment as the target suite. It exercises the target dialog/toggle, Aatrox and Aurora recasts, AA spacing, add/repeat/reorder/remove, item overrides and mitigation, unavailable items, and desktop/mobile overflow. Root and `preview/` runtime files are kept identical.
